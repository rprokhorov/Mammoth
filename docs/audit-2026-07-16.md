## 🔴 P0 — Critical

### P0-1. Токены сессии отдаются во фронтенд и живут в webview-контексте
**Где:** `src-tauri/src/commands/auth.rs` (`LoginResponse.token`), `src-tauri/src/commands/files.rs` → `get_file_url` (`FileUrlResult.token`).

Бэкенд специально перенёс токены в OS keychain (`keychain.rs`) — это правильно. Но `login`/`login_with_token`/`complete_sso_login` **возвращают сырой токен во фронтенд** в `LoginResponse.token`, а `get_file_url` отдаёт `{ url, token }`. Токен попадает в JS-контекст webview, где выполняется отрендеренный markdown с сервера. Любой XSS (см. P1) или скомпрометированная зависимость фронтенда получает bearer-токен на весь аккаунт.

**Что сделать:**
- Убрать поле `token` из `LoginResponse` — фронту токен не нужен, все запросы идут через Rust-команды с токеном из состояния.
- `get_file_url` не должен возвращать токен. Файлы уже качаются через `get_image_data`/`download_file` в Rust — проверить, кто вызывает `get_file_url`, и либо удалить команду, либо возвращать только data-URL/локальный путь.

### P0-2. Уязвимые npm-зависимости (vite high, undici, uuid)
**Где:** `package-lock.json`.

`npm audit`: `vite 8.0.0–8.0.15` — **high** (path traversal + arbitrary file read через dev-server WebSocket), `undici` — TLS bypass / header injection, `uuid <11.1.1` — bounds check. Часть (`vite`, dev-server) актуальна в основном для dev, но undici идёт транзитивно и в рантайме.

**Что сделать:** `npm audit fix` (обновления в пределах semver-мажоров, ломать не должно), затем перепроверить `npm run build` и тесты. Зафиксировать в CI шаг `npm audit --audit-level=high` (не блокирующий на старте, но видимый).

### P0-3. `open_url` открывает произвольный URL из markdown без валидации схемы на бэкенде
**Где:** `src-tauri/src/commands/servers.rs` → `open_url`; вызывается из `src/App.tsx` (перехват кликов по `<a>`) и `MarkdownRenderer`.

`open_url` слепо передаёт `url` в `open`/`xdg-open`/`cmd /c start`. Фронт фильтрует `javascript:`/`data:` в рендерере ссылок, но `open_url` — отдельная Tauri-команда, доступная из любого JS в webview, и вызывается на **любой** клик по ссылке с `href`. На Windows `cmd /c start "" <url>` с подконтрольной строкой — классический вектор инъекции аргументов/запуска локальных путей; `xdg-open`/`open` на путь к файлу или `file://` тоже нежелательны.

**Что сделать:** в `open_url` парсить URL и пропускать только схемы `http`/`https`/`mailto`. Всё остальное — отклонять. На Windows не собирать команду строкой, а использовать `tauri-plugin-opener`/`open` crate.

## 🟠 P1 — High

### P1-1. Path traversal в файловых командах (`save_temp_file`, `download_file`)
**Где:** `src-tauri/src/commands/files.rs` → `save_temp_file` (`temp_dir.join(&file_name)`), `download_file` (`save_path` формируется на фронте как `Downloads/${fileName}`, `fileName` — имя файла **с сервера**).

`file_name`/`fileName` не санитизируются. Имя вида `../../foo` или абсолютный путь вырывается из целевой директории. Источник `download_file.save_path` — имя вложения из поста (управляется отправителем сообщения), т.е. не «своё».

**Что сделать:** в Rust перед записью брать только базовое имя (`Path::new(name).file_name()`), отклонять пустые/traversal-имена, и проверять, что итоговый путь остаётся внутри целевой директории (`canonicalize` + `starts_with`).

### P1-2. `save_temp_file` / `clear_app_cache` работают в общем `std::env::temp_dir()`
**Где:** `files.rs` → `save_temp_file`, `servers.rs` → `clear_app_cache`.

Пишем во всеобщий `/tmp` предсказуемыми именами (`clipboard_<ts>.png`), `clear_app_cache` затем удаляет из `/tmp` **всё**, что подходит под маску `clipboard_*.png` — включая чужие файлы других процессов/пользователей. Плюс symlink-атака в мире-writable `/tmp`.

**Что сделать:** писать во внутренний app-cache dir (`app.path().app_cache_dir()`), не в общий temp. Удалять только из своей поддиректории.

### P1-3. XSS-поверхность в рендеринге сообщений — проверить конфигурацию DOMPurify
**Где:** `src/components/message/MarkdownRenderer.tsx` (`sanitizeHtml`, `ADD_ATTR: ["target"]`), `MermaidBlock.tsx` (`dangerouslySetInnerHTML` для SVG).

Санитизация есть (DOMPurify) — это хорошо. Но:
- `sanitizeHtml` вызывается **после** ручной сборки HTML со вставкой `data-username`/`data-channel` и `href`. Экранирование атрибутов делается своей `escapeAttr` — она покрывает `& " < >`, но полагаться на ручное экранирование хрупко. Убедиться, что DOMPurify — **последний** и единственный барьер, а не «в дополнение к».
- `MermaidBlock` вставляет SVG от mermaid через `dangerouslySetInnerHTML` **без** DOMPurify. `securityLevel: "strict"` у mermaid снижает риск, но SVG всё равно стоит пропускать через DOMPurify (`USE_PROFILES: { svg: true, svgFilters: true }`), т.к. вход — markdown с сервера.

**Что сделать:** прогнать SVG mermaid через DOMPurify; добавить тест-кейсы с payload'ами (`<img onerror>`, `<a href="javascript:">`, `<foreignObject>` в mermaid) в `markdownRenderer.test.tsx`.

### P1-4. `eprintln!` с деталями SSO/куки в проде + токен в логах
**Где:** `src-tauri/src/commands/auth.rs` → `open_sso_window` (много `eprintln!`, включая имена и длины кук), `mattermost/websocket.rs`, `client.rs`.

`open_sso_window` печатает в stderr навигацию, список кук и факт извлечения токена. `eprintln!` работает и в release. Хотя само значение токена не печатается, печатать имена кук и флоу аутентификации в проде не нужно.

**Что сделать:** заменить `eprintln!` на `log::debug!`/`log::trace!` (они и так режутся в release, где логгер поднимается только под `debug_assertions` — см. `lib.rs`). Убедиться, что нигде не логируется значение токена.

### P1-5. WebSocket: жёсткий фронтенд-reconnect дёргает бэкенд, backoff обходится
**Где:** `src/hooks/useWebSocket.ts` (новый `useEffect` с `focus`/`online`/`visibilitychange`), `src-tauri/src/mattermost/websocket.rs`.

Новый код на каждый `focus`/`online`/`visible` зовёт `connect_ws`, который в `auth.rs` **всегда** делает `old.disconnect()` и поднимает новый `WsManager` с нуля. Дебаунс 5 сек есть, но:
- При флаппинге сети (`online` дёргается) это рвёт живое соединение и сбрасывает экспоненциальный backoff бэкенда → шторм переподключений против сервера за reverse-proxy.
- `connect_ws` берёт токен из состояния; если сессия истекла, цикл `ws_loop` будет молча реконнектиться вечно (нет обработки провала auth-challenge как терминального состояния — `handle_message` только логирует `Auth error`).

**Что сделать:** (а) на бэкенде — не пересоздавать WS, если он уже `connected`; ввести «reconnect only if dead». (б) В `ws_loop` при явной ошибке authentication_challenge не уходить в бесконечный reconnect, а эмитить статус `unauthorized` и останавливаться, чтобы фронт показал экран логина.

### P1-6. `connect-src 'self' ipc: http://ipc.localhost` — а картинки/файлы?
**Где:** `src-tauri/tauri.conf.json` → CSP.

CSP разумно строгий (`script-src 'self'`, `object-src 'none'`, `frame-src 'none'`). Всё сетевое ходит через Rust, картинки приходят как data-URL — ок. Но стоит подтвердить, что нигде во фронте не осталось прямых `fetch`/`<img src=https://server>` к Mattermost (иначе они молча блокируются CSP, и это баг). Быстрый греп: прямых `fetch(` к серверу нет — хорошо. Оставить как есть, но зафиксировать инвариант «весь I/O через invoke» в CONTRIBUTING.

### P1-7. `submit_dialog` вызывается на фронте, но команда не зарегистрирована в бэкенде
**Где:** `src/components/message/InteractiveDialogModal.tsx:70,122` вызывает `invoke("submit_dialog", …)`, но в `lib.rs` `invoke_handler` такой команды **нет** (сверено: единственная FE-команда без бэкенда).

Отправка интерактивного диалога (Mattermost interactive message) гарантированно падает с "command not found". Фича нерабочая.

**Что сделать:** реализовать и зарегистрировать `submit_dialog` в Rust (POST на `url` диалога с `submission`/`callback_id`/`state`/`trigger_id`), либо, если фича не нужна, убрать модалку.

### P1-8. Тесты (vitest) не запускаются — воркеры отваливаются по таймауту
**Где:** `vitest.config.ts`, `src/test/*`. `npm test` → `Timeout waiting for worker to respond`, 6 ошибок, `no tests`.

CI гоняет тесты (в workflow есть job `CI`) — если там та же беда, «зелёный» билд обманчив. Возможно, дело в форк-пуле jsdom на этой машине.

**Что сделать:** воспроизвести в CI; попробовать `pool: 'threads'` или `poolOptions.forks.singleFork: true`, поднять `testTimeout`/`hookTimeout`. Починить до того, как полагаться на тесты как на гейт.

## 🟡 P2 — Medium

### P2-1. Настройки в SettingsModal ни на что не влияют
**Где:** `src/stores/settingsStore.ts`, `src/components/user/SettingsModal.tsx`.

`useSettingsStore` читается **только** в самом `SettingsModal`. Ни `theme`, `timeFormat`, `compactMode`, `sendOnEnter`, `showTimestamps`, `notificationsEnabled`, `developerMode` нигде не применяются (grep по всему `src`). Пользователь тумблерит — ничего не меняется. `theme` в MermaidBlock захардкожен `"dark"`.

**Что сделать:** либо подключить настройки к поведению (тема через data-атрибут на `<html>` + CSS-переменные; `sendOnEnter` в композере; `notificationsEnabled` как гейт в `useWebSocket` перед `show_notification`; `timeFormat`/`showTimestamps` в рендере времени), либо убрать неработающие тумблеры, чтобы не вводить в заблуждение.

### P2-2. `IDLE_TIMEOUT`/ping могут ложно рвать соединение при переходе ноутбука в сон
**Где:** `src-tauri/src/mattermost/websocket.rs`.

`ping_timer` использует `tokio::time::interval` — во время сна ОС таймеры «схлопываются», после пробуждения может выстрелить пачка тиков, а `last_activity.elapsed()` окажется > `IDLE_TIMEOUT` → немедленный разрыв. В связке с P1-5 (фронт тоже дёргает reconnect на wake) это двойной реконнект. Логика в целом верная, но стоит: игнорировать первый тик после долгого простоя и сверять с реальным wall-clock.

**Что сделать:** после пробуждения (детект по большому фактическому интервалу между тиками) сбрасывать `last_activity`, а не считать соединение мёртвым сразу.

### P2-3. `save_post`/`unsave_post` дублируют preferences-логику вместо общих helpers
**Где:** `src-tauri/src/mattermost/client.rs` — `save_post`/`unsave_post` собирают preferences вручную, хотя рядом есть `save_preferences`/`delete_preferences`.

Дублирование формата preferences в двух местах → риск рассинхрона. Не баг, но техдолг.

**Что сделать:** выразить `save_post`/`unsave_post` через `save_preferences`/`delete_preferences`.

### P2-4. Гонки/утечки в in-memory кэшах фронтенда
**Где:** `src/hooks/useUserAvatar.ts` (module-level `Map` cache/pending/listeners), `useWebSocket.ts` (`typingTimers` Map).

`cache`/`pending` в `useUserAvatar` — глобальные и **никогда не чистятся** (кроме точечного `clearUserAvatarCache`). При долгой сессии с тысячами пользователей растёт неограниченно (каждый аватар — base64 data-URL в памяти). `typingTimers` чистится по таймеру — ок, но при размонтировании хука таймеры не отменяются.

**Что сделать:** ограничить размер avatar-кэша (LRU) или инвалидировать по серверу/времени; отменять `typingTimers` при cleanup.

### P2-5. `restore_servers`/`init` молча проглатывают ошибки, UI уходит «в оффлайн» по строковому матчингу
**Где:** `src/App.tsx` `loadServers` — определение «оффлайна» через `msg.includes("network"|"timeout"|"os error")`.

Матчинг по подстроке в тексте ошибки хрупок (локализация, смена формулировок в reqwest → «онлайн»-ошибка уедет в оффлайн-ветку или наоборот). Лучше — типизированный признак ошибки из Rust.

**Что сделать:** возвращать из бэкенда структурированный `AppError` с дискриминатором (в JSON), а не только строку; на фронте матчить по коду, не по тексту.

### P2-6. `println!/console.log` и `dbg`-подобные логи в проде-фронте
**Где:** `useWebSocket.ts` (`console.log("WS event (unhandled)"`, `open_dialog WS event data`), `App.tsx` (`[notif]`, `[emoji]`), и др.

Много `console.log` с полным дампом payload'ов (включая тела сообщений) в проде. Шум + потенциальная утечка контента в devtools-лог.

**Что сделать:** завести обёртку-логгер с уровнем, гейтить debug-логи по `developerMode`/`import.meta.env.DEV`.

## ⚪ P3 — Low / качество

- **P3-1. `docker/docker-compose.yml`** — тестовый Mattermost с `ENABLEOPENSERVER=true`, `ENABLELOCALMODE=true`, дефолтным паролем (значение не публикуется), `sslmode=disable`. Это dev-only, но добавить явный комментарий «НЕ для прод» и вынести пароль в `.env`.
- **P3-2. `.env.example`** — упоминает `MATTERMOST_TOKEN` «for development only»; убедиться, что приложение реально не читает токен из env в проде (не нашёл — ок, но зафиксировать).
- **P3-3. `Cargo.toml`** — `tauri` собран с фичей `devtools` без `cfg(debug_assertions)`-гейта → devtools доступны в release-бандле. Убрать `devtools` из релизной сборки.
- **P3-4. `authors = [""]`, `repository = ""`** в `Cargo.toml`; пустой `author` в `package.json` — заполнить метаданные.
- **P3-5. `rand_jitter()`** в websocket.rs — самодельный PRNG из наносекунд системного времени. Работает, но при одновременном реконнекте нескольких серверов даёт коррелированный jitter. Мелочь; можно взять `fastrand`.
- **P3-6. Мусорные файлы в корне репозитория** — `plan.md`, `todo.md`, `features.md` (57 КБ), `.ralphex/`. Перенести в `docs/` или почистить; `todo.md` смешивает сделанное и несделанное.
- **P3-7. ESLint правила** `react-hooks/set-state-in-effect|refs|immutability` стоят в `warn` с комментарием «tracked separately» — завести issue, чтобы не забылось.
- **P3-8. `#[allow(dead_code)]`** на ~10 методах `MattermostClient` («API surface, not wired yet») — либо задействовать, либо удалить, чтобы не тащить мёртвый код.
- **P3-9. `get_server_version`** парсит `X-Version-Id`, при отсутствии лезет в JSON `/system/ping` — но `/system/ping` не возвращает `version` в body у многих версий; фолбэк вернёт `"unknown"`. Не критично.
